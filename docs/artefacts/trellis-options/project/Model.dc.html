THE MODEL

Three things, and one question about every file

"Virtual repo" mixes two separate questions: what a thing is, and where its file is kept. Answer them separately and the page needs three nouns and one badge.

REPO
What one repo runs
Its apps, jobs and infra; the values it offers; the values it needs from somewhere else.
shop-services
runs catalog-api, orders-api, migrate
offers catalog-url, orders-url
needs mail-smtp
→
TRELLIS
Which repos run together, and how
Picks repos, adds shared infra, fills any need no repo offers, and sets worktrees, ports and groups.
storefront
shop-services + shop-web + shop-mobile
adds mail, which fills mail-smtp
worktrees from main · stable ports
→
SPROUT
One running copy, for one task
Its own worktrees (or the checkout), ports, data and logs. Made from a trellis; many per trellis.
storefront · feat-a
branch feat-a, ports 8000–8010
4 of 4 apps running
WHERE ITS FILE IS KEPT · SAME FOR REPOS AND TRELLISES
in repo
Committed beside the code, so the team shares it. Follows branches: a sprout runs its branch's version. Sprig asks before running a version you haven't approved.
in sprig
Kept on this machine; nothing is written to your repos. The same for every sprout, since no branch can change it. Saving it approves it.
One action each way, on the thing itself: Keep in sprig or Put in the repo. "Virtual", "written in sprig", "referenced" and "copy into sprig" all become this one badge.
